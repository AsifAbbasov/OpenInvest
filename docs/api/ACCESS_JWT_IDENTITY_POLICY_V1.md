# ACCESS_JWT_IDENTITY_POLICY_V1 — approved contract summary
**Problem / Root Cause:** The access verifier previously allowed missing/inconsistent canonical identity claims despite a valid signature.
**Risk:** Conflicting user identities could reach authorization consumers; financial isolation requires the validated signed investment subject independently of user identity.
**Alternatives:** Legacy fallback, identity normalization/substitution and unrelated future-iat/parser changes were rejected or separately governed.
**Decision:** `sub`, `uid`, `investmentSubjectId` MUST be present and non-empty; `sub` MUST equal `uid` exactly; reject missing/empty/inconsistent identities; no legacy fallback.
**Rationale:** Keep one explicit signed identity contract; financial authorization MUST retain validated `investmentSubjectId`; preserve existing HS256 signature, expected algorithm/type and expiration validation.
**Implementation:** Accepted PR266 is integrated by [PR268](https://github.com/AsifAbbasov/OpenInvest/pull/268) at `3e2ca51f761a1f8ea92370f666cf636b9de3b600`; [complete normative contract, issuer/consumer trace, HTTP401 semantics and original source hashes](https://github.com/AsifAbbasov/OpenInvest/blob/3e2ca51f761a1f8ea92370f666cf636b9de3b600/docs/api/ACCESS_JWT_IDENTITY_POLICY_V1.md).
**Verification:** Both original JWT01 assertions, login/refresh and bidirectional PostgreSQL financial isolation remain covered; technical acceptance PASS; [post-merge CI 38758661473](https://github.com/AsifAbbasov/OpenInvest/actions/runs/38758661473) SUCCESS 10/10; historical original RED sources unchanged.
**Limitations:** No `iat`/duplicate-claim policy change, per-request session lookup or signing-key compromise protection; JWT02 Option A residual approved, JWT03 informational; untracked deployed issuers are not certified.
